This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
flutter pub get

# Run the app (pick a connected device/simulator, or use -d <device_id>)
flutter run

# Format code — 반드시 소스 디렉터리를 지정할 것 (아래 참고)
dart format lib test integration_test
```

- `dart format .`(프로젝트 루트 전체)은 쓰지 않는다. Firebase 연동(SPM) 때문에 `flutter pub get`을 실행할 때마다 `build/ios/SourcePackages/`에 플러그인 소스 캐시가 재생성되는데, `dart format`은 `build/`도 재귀 스캔하고 `analysis_options.yaml`의 `analyzer.exclude`도 적용받지 않아 그 안의 `example` 앱 때문에 매번 `Warning: Couldn't read file ...analysis_options.yaml` 경고가 뜬다(포맷 자체는 무해하게 완료됨). `flutter clean`으로도 근본 해결이 안 되므로(재생성됨), 위처럼 실제 소스 디렉터리(`lib test integration_test`)만 지정해서 포맷한다.

## Project Overview

**널널**은 인파를 피해 여유롭고 쾌적한 여행을 원하는 자유여행객을 위한 AI 여행 챗 비서 모바일 앱이다. 실시간 혼잡도 데이터를 기반으로 한적한 대안 여행지를 매칭하고 과밀 분산 여행 코스를 추천한다(자세한 제품 컨셉·화면 스펙은 `docs/DESIGN.md` 참고).

- 대상 플랫폼: iOS, Android (`## 플랫폼 지원` 참고)
- 현재 단계: `lib/data/demo_script.dart`의 canned 스크립트로 동작하는 프로토타입으로, 실제 백엔드/AI 연동은 아직 없다.
- 화면 흐름: 스플래시(브랜드 등장 애니메이션) → 로그인(SNS 전용) → 채팅(빈 상태 / 대화) → 지난 대화(히스토리) → 설정, `go_router`(`lib/app_router.dart`)의 평면(flat) 경로 구성으로 이루어진 단일 스택 내비게이션. 채팅 내 장소 추천 아이템 탭 시 장소 상세 화면으로 별도 이동. 온보딩 화면은 코드/라우트(`/onboarding`)는 유지하되 현재 화면 흐름에서는 제외되어 있다(스플래시가 곧바로 로그인으로 전환).

## Architecture

Flutter 앱 "널널"(package name `nullnull`, Dart SDK `^3.6.1`)은 AI 여행 챗봇 서비스로, `docs/DESIGN.md`에 정의된 화면 구성(온보딩 → 채팅 → 지난 대화 → 설정)을 기반으로 하되, 앱 최초 진입 시 노출되는 스플래시 화면(`splash_screen.dart`), 온보딩과 채팅 사이에 SNS 전용 로그인 화면(`login_screen.dart`), 채팅 내 장소 추천 아이템 탭 시 이동하는 장소 상세 화면(`place_detail_screen.dart`)이 추가되어 있다(`docs/DESIGN.md`에는 아직 반영되지 않음). 온보딩 화면(`onboarding_screen.dart`)은 코드와 `/onboarding` 라우트가 그대로 남아 있으나, 현재는 화면 흐름에서 제외되어 스플래시에서 바로 로그인 화면으로 이동한다.

- `lib/main.dart` — 앱 진입점. `WidgetsFlutterBinding.ensureInitialized()` 직후 `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`(`lib/firebase_options.dart`, `flutterfire configure`로 생성됨)로 Firebase를 가장 먼저 초기화하고, 곧바로 `CrashReportingService.ensureInitialized()`로 Crashlytics 에러 핸들러를 등록한다. 이어서 `AppInfo.ensureInitialized()`와 `AppTextScaleController.ensureInitialized()`를 초기화한 뒤 전역 `appTextScaleController`(`late final`)를 통해 `MaterialApp`을 `ValueListenableBuilder<AppFontScale>`로 감싸고, `builder`에서 `MediaQuery`의 `textScaler`를 선택된 배율로 덮어써 앱 전체 글자 크기에 적용한다. 화면 모드(다크 모드) 전환 기능은 사용하지 않는다(`theme: AppTheme.theme` 고정). `MaterialApp`에 전역 `navigatorKey`를 지정하고, `builder`에서 가장 바깥쪽을 `HealthCheckGate`로 감싸 앱 실행 시 백엔드 헬스 체크를 수행하고, 그 안쪽을 다시 `NetworkStatusListener`로 감싸 네트워크 연결 끊김을 앱 어디서든 감지한다. 그 안쪽을 다시 `GestureDetector(behavior: HitTestBehavior.opaque)`로 감싸 빈 화면을 탭하면 `FocusManager.instance.primaryFocus?.unfocus()`로 키보드를 앱 어디서든 내린다.
- `lib/app_info.dart` — 서비스명, 개발자 이메일, 개인정보처리방침/스토어 URL 등 앱 메타데이터와 `package_info_plus` 기반 `PackageInfo`를 전역으로 제공한다.
- `lib/app_log.dart` — `logger` 패키지를 감싼 `AppLog.logger` 전역 로거.
- `lib/app_config.dart` — 백엔드/외부 서비스 연동 설정. `baseUrl`(`https://nullnull.kr`)과 `healthzEndpoint`(`/api/v1/healthz`)·`attributionEndpoint`(`/api/v1/meta/attribution`)·`chatStreamEndpoint`(`/api/v1/chat/stream`)·`chatSessionsEndpoint`(`/api/v1/chat/sessions`)·`chatSessionMessagesEndpoint(sessionId)`/`chatSessionStreamEndpoint(sessionId)`/`chatSessionEndpoint(sessionId)`(경로에 `session_id`가 들어가 함수로 정의)는 `docs/API_SPEC.md`로 확정된 실제 값이고, `congestionEndpoint`/`alternativesEndpoint`는 아직 명세서에 경로가 정리되지 않아 플레이스홀더로 남아 있다. 카카오 로그인 SDK(`kakao_flutter_sdk_user`) 초기화용 `kakaoNativeAppKey`도 여기 있으며 `main.dart`의 `KakaoSdk.init`에서 사용한다.
- `lib/double_back_exit_mixin.dart` — `DoubleBackExitMixin` — 2초 안에 뒤로가기를 두 번 연속 입력하면 `flutter_exit_app`으로 앱을 종료하는 mixin. 첫 번째 입력에는 `AppToast`로 안내만 띄운다. 뒤로 나갈 화면이 없는 `ChatScreen`(로그인 성공 시 `go_router` 스택이 `/chat` 하나만 남는 홈 화면)에서 `PopScope(canPop: false)` + `onPopInvokedWithResult`로 적용한다.
- `lib/app_router.dart` — 앱 전역 `GoRouter`(`appRouter`)와 그 `navigatorKey`(`rootNavigatorKey`, `NetworkStatusListener`의 오프라인 팝업 오버레이 컨텍스트 확보용)를 정의한다. `observers`에 `AnalyticsService.observer`(`FirebaseAnalyticsObserver`)를 등록해 화면 전환을 Firebase Analytics에 자동 기록한다. 경로는 `/splash`(`initialLocation`, 앱 최초 진입 화면), `/onboarding`, `/login`, `/chat`, `/history`, `/settings`, `/place`(장소 상세, `PlaceRecommendation`을 `extra`로 전달)로 중첩 없이 평면 구성한다. 각 `GoRoute`는 `RouteNames`(같은 파일에 정의된 `static const` 문자열 모음)로 이름을 가지며, 화면 코드에서는 경로 문자열을 하드코딩하지 않고 항상 `context.pushNamed(RouteNames.xxx)`(스택에 쌓기)/`context.pop()`(뒤로가기)/`context.goNamed(RouteNames.xxx)`(현재 스택을 교체 — 로그인 성공, 로그아웃처럼 이전 화면으로 못 돌아가야 하는 경우)를 상황에 맞게 쓴다. `showDialog`로 띄우는 팝업(`_ConfirmDialog` 등)과 `LicensePage`처럼 자체 URL이 필요 없는 화면은 `go_router` 경로에 넣지 않고 기존처럼 `Navigator.of(context)`로 직접 다룬다.
- `lib/screens/` — `splash_screen.dart`, `onboarding_screen.dart`, `login_screen.dart`, `chat_screen.dart`, `history_screen.dart`, `settings_screen.dart`, `place_detail_screen.dart`. `splash_screen.dart`는 `go_router`의 `initialLocation`(`/splash`)으로 앱 최초 진입 시 노출되며, 마스코트(`widgets/nullnull/mascot.dart`)와 워드마크에 페이드·스케일 등장 애니메이션(`AnimationController`)을 적용한 뒤 고정된 지연 시간(`Timer`) 후 `context.goNamed(RouteNames.login)`으로 로그인 화면으로 자동 전환한다(뒤로가기로 스플래시로 못 돌아오도록 스택을 교체). `onboarding_screen.dart`는 `/onboarding` 라우트로 여전히 존재하지만 현재는 어떤 화면에서도 진입 경로가 연결되어 있지 않다(코드 삭제 없이 화면 흐름에서만 제외, 재도입 시 스플래시의 전환 대상만 되돌리면 됨). `login_screen.dart`는 카카오 SNS 로그인만 제공(회원가입 절차 별도 없음)한다(네이버는 SDK 연동 전 mock 단계였던 로그인 버튼을 완전히 제거함 — `SnsProvider` enum도 `kakao` 하나만 남음). `kakao_flutter_sdk_user`로 실제 로그인 후 `_loginWithKakao`가 `AuthService.loginWithKakao(token.accessToken)`으로 백엔드와 토큰을 교환해 `AuthTokenStorage`에 저장한다(`## API`의 `auth` 문단 참고, 실기기/시뮬레이터에서 로그인 성공까지 확인 완료). 이어서 `_saveKakaoProfile`이 `UserApi.instance.me()`로 카카오 프로필(닉네임/프로필 사진 URL은 `kakaoAccount.profile`, 이메일은 `kakaoAccount.email`)을 조회해 `UserProfileStorage`에 저장한다(동의 안 한 항목은 `null`로 와 저장에서 걸러짐, 조회 자체가 실패해도 로그인 플로우는 계속 진행) — `settings_screen.dart`와 `chat_screen.dart`의 프로필 아바타가 이 값을 읽어 반영한다. 하단 SNS 버튼 카드의 바닥 여백은 `MediaQuery.paddingOf(context).bottom`과 최소값(`_minBottomCardPadding`, 24) 중 큰 쪽을 쓴다 — iOS는 홈 인디케이터 때문에 이 시스템 인셋이 항상 0보다 크지만, 안드로이드는 제스처 내비게이션이어도 에뮬레이터/실기기에서 0으로 오는 경우가 있어(라이브 로그로 확인함: `padding.bottom`/`viewPadding.bottom`/`viewInsets.bottom` 전부 0.0) 시스템 인셋에만 의존하면 버튼이 화면 맨 아래에 여백 없이 붙어 보인다. `chat_screen.dart` 헤더 우측의 프로필 아바타(`_ProfileAvatarButton`)는 `UserProfileStorage`에 저장된 실제 프로필 사진이 있으면 `ProfileAvatar`(`widgets/nullnull/profile_avatar.dart`, `settings_screen.dart`와 공유)로 그걸 보여주고, 없으면 닉네임(역시 `UserProfileStorage`가 있으면 그 값, 없으면 `DemoUser` 목업) 첫 글자로 대체한다. 빈 대화 상태(`_EmptyState`)의 인사말(`l10n.chatGreeting`)도 같은 패턴으로 `UserProfileStorage`의 실제 닉네임을 우선 쓰고 없으면 `DemoUser` 목업으로 대체한다 — 이전에는 `_ProfileAvatarButton`만 실제 닉네임을 쓰고 이 인사말은 항상 데모 목업이라 서로 표시가 어긋났었다. 탭하면 `CompositedTransformTarget`/`CompositedTransformFollower`(`LayerLink`)로 아이콘 바로 아래에 `assets/images/popup_slot.png` 배경의 팝업(`_ProfileMenuCard`, 154×77)을 띄운다. 팝업은 "설정"/"로그아웃" 2개 메뉴로 구성되며, 화면 전체를 덮는 투명 배리어를 탭하면 닫힌다. "설정" 탭 시 `context.pushNamed(RouteNames.settings)`로 이동하고, "로그아웃" 탭 시 `ConfirmDialog`로 확인한 뒤 메뉴를 닫고 `_showLoadingOverlay()`로 전역 `Overlay`에 화면 전체를 덮는 로딩 오버레이(`_FullScreenLoadingOverlay`, `settings_screen.dart`의 `_isLoggingOut` 오버레이와 같은 모양이지만 이 위젯엔 전용 `Scaffold`가 없어 `_menuEntry`와 같은 `OverlayEntry` 메커니즘으로 구현)를 띄운 채 `LogoutService.logout()`을 기다린 뒤 오버레이를 지우고 `context.goNamed(RouteNames.login)`으로 이동한다(`settings_screen.dart`와 동일한 서비스를 공유하되 오버레이 구현 방식만 다름). 메시지 전송은 `lib/api/chat_api.dart`의 `ChatApi`(`_ChatScreenState._chatApi`)로 처리한다: `_send`가 `ChatApi.sendMessage(text:, sessionId: _sessionId)`가 반환하는 SSE 이벤트 스트림을 `await for`로 순서대로 소비하되, 다른 생성형 AI 도구들처럼 응답을 일정한 리듬으로 보여주기 위해 도착하는 대로 화면에 반영하지 않는다 — `ChatDeltaEvent`/`ChatCardEvent`(카드는 `ChatCardEvent.demoBlock` — 실제 백엔드 카드 JSON 스키마가 아직 없어 `MockChatApi`가 원본 `AiBlock`을 그대로 실어 보내는 지름길, 없으면 `ChatCardBlock(type, payload)`, `## API` 참고)는 로컬 `buffer`에만 모아두고, `ChatSourcesEvent`(`{name, note}` 목록)도 `capturedSources`에만 모아둔다. 화면에는 대신 `ChatStatusEvent`의 라벨(`_AiChatEntry.statusLabel`)만 실시간으로 갱신해 진행 상황(`_ThinkingIndicator`)을 보여준다. `ChatMetaEvent`로는 세션을 갱신한다. 스트림이 완전히 끝나면(`await for` 정상 종료, `final`/`done`까지 다 옴) 모아둔 buffer·출처를 `_AiChatEntry.blocks`/`.sources`에 한 번에 채워 넣는다 — 그 순간 `_ThinkingIndicator` 대신 `StreamingAiMessage`(`widgets/chat/streaming_ai_message.dart`)가 처음 마운트되고, 이 위젯이 직접 내부 `_reveal()`(`Timer` 대신 `Future.delayed` 루프, 문장은 2자씩/20ms 간격, 블록 사이 200ms 정지)로 타이핑 연출을 진행한다. 연출이 끝나면 위젯이 커서를 멈추고, 출처가 있으면 응답 하단에 작게 나열한 뒤(`_SourcesFooter`, 실 서버 `name`에 이미 "출처: ⓒ..." 안내 문구가 포함돼 있어 별도 헤더 없음), `onRevealComplete` 콜백으로 `_ChatScreenState`에 알려 `_AiChatEntry.done = true`를 켜고 `MessageActionsRow`(복사/재생성)를 노출한다 — 재생성(`_regenerate`)·지난 대화 이어보기(`_applyResume`)는 이미 완성된 블록을 `streaming: false`로 곧바로 넘겨 타이핑 연출 없이 즉시 전체를 보여준다. 스트림 에러(`ChatErrorEvent` 포함)는 잡아서 해당 AI 엔트리를 제거하고 `AppToast`(l10n `chatSendFailedToast`)로만 안내하며 **자동 재시도하지 않는다**(`docs/API_SPEC.md`의 재연결 금지 규칙). "새 대화"(`_newChat`)는 `_sessionId`를 `null`로 되돌려 다음 메시지부터 새 세션이 발급되게 한다. `ChatScreen`도 이제 생성자 `chatApi` 파라미터로 테스트 시 주입 가능(`history_screen.dart`와 동일한 패턴 — `PushDrawer`에 항상 함께 마운트되는 `AppDrawer`가 세션 목록을 실 서버에서 가져오게 되면서, 위젯 테스트에서 `ChatScreen`을 띄우면 이 요청까지 함께 나가 `MockChatApi` 주입이 필요해짐). `_chatApi`는 기본값이 `LoggingChatApi(DioChatApi(ApiClient.create()))`로, 실제 `nullnull.kr`(`docs/API_SPEC.md`의 `POST /api/v1/chat/stream`)에 붙는다 — 로그인 후에는 `ApiClient.create()`가 붙이는 `Authorization` 헤더로 인증까지 되는 것을 시뮬레이터에서 확인함(로그인 전이거나 액세스 토큰이 만료되면 여전히 `401`, `_send`가 이를 잡아 실패 토스트만 띄운다). 카드 자체의 실제 파싱/렌더링은 `widgets/nullnull/chat_card_view.dart`가 그리기 시점에 `type`을 보고 한다(실 서버에서 확인된 `attraction_list`/`crowd` 두 카드 타입 지원, 그 외 타입은 로그만 남기고 조용히 스킵). 데모 스크립트로 되돌리려면 `LoggingChatApi(MockChatApi())`로 바꾸면 된다. `history_screen.dart`(`HistoryScreen`)는 지난 대화 목록 화면으로, `AppDrawer`의 "최근" 섹션 라벨(탭하면 `context.pushNamed(RouteNames.history)`)이 진입 지점이다. `docs/DESIGN.md`에 이 화면의 레이아웃 스펙이 없어 `place_detail_screen.dart`(색상/타이포그래피 컨벤션)를 그대로 따라 구성했고, 상단 바는 `settings_screen.dart`와 같은 `nullnull/plain_header.dart`의 `PlainHeader`(뒤로가기 + 가운데 타이틀, 배경 슬롯 이미지 없음)를 쓴다. `lib/api/chat_api.dart`의 0이었음. 세션 목록/메시지 이력/삭제는 공통 응답 봉투를 언래핑(`_unwrap`)해 실패 시 `ChatApiException`을 던진다. 단, **[실서버로 확인함]** 세션/메시지 `data` 하위 필드명은 처음엔 `sessions`/`session_id`/`messages`/`text`로 가정했으나, 실제로는 `items`(목록 키, 세션·메시지 공통)/`id`(세션 id 키, `session_id` 아님)/`content`(메시지 본문 키, `text` 아님)였다 — 그 전까지는 실제로 세션/메시지가 있어도 `fetchSessions`/`fetchMessages`가 항상 빈 목록을 반환하고 있었음(파싱 실패가 `null ?? []`로 조용히 흡수됨, `history_screen.dart`가 지속적으로 "아직 지난 대화가 없어요"만 보여준 원인이었다). `hasMore`도 최상위가 아니라 세션 목록에 한해 `page.has_more`로 확인됨. 메시지의 `id`는 문자열이 아니라 숫자로 와서 `ChatMessage.fromJson`이 `toString()`으로 변환한다. 메시지 응답에는 이 외에도 `tool_trace`(SSE `card` 이벤트와 동일한 카드 데이터)가 함께 오지만 아직 `ChatMessage`에 반영 안 함(`ChatMessage` 클래스 문서 참고, 대화 이어보기 시 카드가 유실되는 원인). 메시지 쪽 페이징 필드명(`next_before` 등)은 응답에 페이지가 하나뿐이라 미확인 상태로 남아 있다. SSE 프레임 `data` JSON 필드명 중 아직 명세서/실서버로 확인 못한 것들은 가정한 값이다 — 확정되면 `_parseSseFrame`과 각 `fromJson`만 갱신하면 되도록 분리해둠. `api_client.dart`(`AppConfig` 설정을 적용한 공용 `Dio` 인스턴스를 만드는 `ApiClient.create()`)는 `_AuthInterceptor`(같은 파일의 프라이빗 클래스, 생성한 `Dio` 자기 자신을 들고 있어 재시도 시 재사용)로 매 요청 직전에 `AuthTokenStorage.read()`를 조회해 토큰이 있으면 `Authorization: Bearer <token>`을 자동으로 붙인다(인증이 필요 없는 `healthz`/`attribution`에도 함께 실리지만 서버가 무시해 무해함). 401을 받으면 `onError`에서 `AuthService.refresh()`를 호출해 갱신 후 원 요청을 재시도하고(`options.extra['authRetried']`로 한 번만), 그마저 실패하면 원래 401을 그대로 전달한다(`## API`의 `auth` 문단 참고, 시뮬레이터에서 라이브로 확인 완료). 이 401→refresh→재시도 흐름은 `AppLog.logger`로 로그를 남긴다(`w`: 401 감지, `i`: 재시도 성공, `e`: refresh/재시도 실패) — 콘솔에서 바로 확인할 수 있도록 의도적으로 유지 중. `attribution_service.dart`/`health_check_service.dart`뿐 아니라 이제 `DioChatApi`에서도 이 클라이언트를 쓴다.

## API

백엔드 API 연동 공통 규칙(응답 봉투, 엔드포인트 목록 등)은 `docs/API_SPEC.md`를 기준으로 삼는다(현재 전달받은 내용까지만 정리된 미완성 문서). `lib/api/` 하위 API 클라이언트 코드를 새로 만들거나 수정하기 전에 먼저 `docs/API_SPEC.md`를 확인할 것 — 특히 응답은 SSE/SSF 예외를 제외하면 모두 `success`/`code`/`message`/`data`/`retriable`/`timestamp` 봉투로 오며, `success: true`이면서도 `data.status`가 `no_data` 등으로 빈 결과를 나타낼 수 있으므로 봉투 언래핑과 `data.status` 확인을 분리된 타입가드로 구현해야 한다.

`chat` 엔드포인트(`POST /api/v1/chat/stream`(SSE), `GET /api/v1/chat/sessions`, `GET /api/v1/chat/sessions/{session_id}/messages`(커서 페이징, `before`), `GET /api/v1/chat/sessions/{session_id}/stream`(끊긴 스트림 이어받기), `DELETE /api/v1/chat/sessions/{session_id}`, 모두 인증 필요)는 `lib/api/chat_api.dart`의 `DioChatApi`/`lib/app_config.dart`의 `chat*Endpoint`로 실제 구현돼 있고, `ChatScreen`/`HistoryScreen`이 이미 실사용 중이다(`lib/screens/` 참고 — 인증 미구현이라 현재는 모든 호출이 `401`). 실제 연동 시 주의할 점: `POST`라 `EventSource`를 못 쓰므로 `fetch`/`Dio`의 스트림 응답 파싱으로 `meta`→`status`→`tool`→`card`→`delta`→`sources`→`final`→`done`(실패 시 `error`) 순서를 처리해야 하고, 스트림이 끊겨도 **자동 재연결 금지**(중복 처리로 비용 2배)이며 재시도는 사용자 버튼으로만 한다. 새 대화는 `session_id`를 비워 보내고 최초 `meta`로 받은 값을 이후 메시지에 계속 실어 보낸다. 카드가 문장(`delta`)보다 먼저 도착할 수 있어 도착 순서대로 렌더링하고, 수치가 다르면 카드가 원본이다. `card.payload.status`가 `no_data`/`has_data:false`면 카드 대신 후속 질문 버튼을 그린다.

`auth` 엔드포인트(`POST /api/v1/auth/oauth/{provider}/callback`(카카오 소셜 로그인, `provider=kakao`만 허용, 웹은 `code`+`redirect_uri`/앱은 `access_token`)·`POST /api/v1/auth/dev-login`·`POST /api/v1/auth/login`(관리자 로컬, 5회 실패 시 10분 잠금)·`POST /api/v1/auth/refresh`·`POST /api/v1/auth/logout`·`GET`/`DELETE /api/v1/me`·`POST /api/v1/auth/kakao/webhook`(SSF, 공통 봉투 아님, RS256 서명 JWT)·`GET /api/v1/auth/providers`)는 명세가 확정돼 있고(`docs/API_SPEC.md`), 로그인 작업을 단계별로 진행 중이다: 1) `lib/data/auth_token_storage.dart`의 `AuthTokenStorage`(`flutter_secure_storage`, iOS Keychain/Android Keystore)가 `AuthTokens(accessToken, refreshToken)`을 저장, 2) `lib/data/auth_service.dart`의 `AuthService.loginWithKakao(kakaoAccessToken)`이 `POST /api/v1/auth/oauth/kakao/callback`으로 실제 교환해 저장까지 하고(`login_screen.dart`의 `_loginWithKakao`가 카카오 SDK 토큰을 받은 직후 호출 — 실제 기기/시뮬레이터에서 로그인 성공까지 확인 완료), 3) `lib/api/api_client.dart`의 `ApiClient.create()`가 `_AuthInterceptor`(구 `_AuthHeaderInterceptor`)로 저장된 토큰을 모든 요청에 `Authorization: Bearer <token>`으로 자동 부착한다(마찬가지로 확인 완료), 4) 같은 `_AuthInterceptor.onError`가 401을 받으면 `AuthService.refresh()`(`POST /api/v1/auth/refresh`)를 호출해 딱 1회 갱신 후 원래 요청을 재시도한다(`options.extra['authRetried']`로 재시도 표시해 재귀 방지, `/auth/refresh` 자기 자신의 401은 애초에 건너뜀). `AuthService.refresh()`는 정적 필드(`_refreshInFlight`)로 앱 전체에서 진행 중인 갱신 하나만 공유해 **동시에 여러 갱신 요청을 보내지 않는다**(`docs/API_SPEC.md` 규칙). 갱신 실패 시(서버가 명시적으로 거절한 경우만, 네트워크 오류는 제외) `AuthTokenStorage.clear()`로 로컬 토큰을 비운다. 이어서 `_AuthInterceptor.onError`가 (refresh 실패 직후) `AuthTokenStorage.read()`로 토큰이 정말 지워졌는지 한 번 더 확인해 — 지워졌으면(=서버가 명시적으로 거절한 진짜 세션 만료, 네트워크 오류로 토큰이 그대로 남아있는 경우는 제외) `AppToast`로 `authSessionExpiredToast`("세션이 만료됐어요. 다시 로그인해주세요.") 안내 후 `appRouter.goNamed(RouteNames.login)`으로 로그인 화면으로 스택을 교체한다. `BuildContext` 없이 인터셉터(데이터 계층)에서 바로 호출해야 해서 `app_toast.dart`와 동일하게 `rootNavigatorKey`를 통해 얻은 컨텍스트를 쓴다(`api_client.dart`가 `app_router.dart`를 import하는 게 유일한 예외처럼 보이지만, `app_toast.dart`가 이미 같은 패턴으로 `app_router.dart`를 참조하고 있어 기존 컨벤션과 일치함). 401→refresh→재시도 성공 전 과정과, refresh 자체가 서버 거절로 실패해 로그인 화면으로 리다이렉트되는 전 과정 모두 시뮬레이터에서 라이브로 확인함(액세스+리프레시 토큰을 모두 의도적으로 깨뜨려 실제 401→refresh 거절을 유발 → 콘솔 로그로 `401 → refresh 시도`/`refresh 실패 → 원래 401 전달` 확인 → 로그인 화면으로 자동 이동 확인). `_AuthInterceptor`의 `AppLog.logger` 로그(`[Auth] ... 401 → refresh 시도` / `refresh 성공, ... 재시도 성공` / 실패 시 `e` 레벨)가 이 과정을 콘솔에서 보여준다. 5) `logout_service.dart`의 `LogoutService.logout(provider)`가 provider와 무관하게 먼저 `AuthService.logout()`(`POST /api/v1/auth/logout`, 저장된 토큰을 직접 읽어 헤더에 실어 보냄 — 토큰이 없으면 요청 없이 스킵)을 호출해 백엔드 세션을 정리하고 `AuthTokenStorage.clear()`로 로컬 토큰을 지운 뒤, 카카오라면 기존처럼 SDK 로그아웃도 호출한다. 요청 실패는(네트워크 오류 등) 로깅만 하고 항상 로컬 로그아웃을 진행한다(카카오 SDK 로그아웃 실패를 다루던 기존 방식과 동일). 로그인 작업 5단계 모두 구현 완료. 추가로 `AuthService.withdraw()`가 `DELETE /api/v1/me`(회원 탈퇴, 카카오 연결 해제까지 서버가 함께 처리)를 구현해 `settings_screen.dart`의 "연결 끊기"가 사용한다(`## Architecture`의 `settings_screen.dart` 항목 참고). 액세스 토큰은 30분, 리프레시 토큰은 14일 유효.

### Dart / Flutter 스타일

- 불변 위젯과 값에는 `const` 키워드를 우선 사용한다.
- 재사용 단위의 UI 블록은 프라이빗 클래스(`_WidgetName`)로 분리한다.
- 인스턴스화가 불필요한 유틸 클래스는 `private constructor` + `static` 멤버 패턴을 유지한다. (`AppColors`, `AppLog` 참고)
- `late final`을 적극 활용하여 불필요한 nullable을 줄인다.
- `SafeArea` 위젯 사용 시, `maintainBottomViewPadding: true` 값을 기본으로 사용한다.
- `SingleChildScrollView` 위젯 사용 시, `physics: const BouncingScrollPhysics()` 값을 기본 값으로 사용한다.
- 간단히 실행되는 함수의 경우 블록형 보다는 화살표 형으로 작성한다. (router 쪽은 블록형으로 작성하도록 놔둘 것.)
- analysis_options.yaml 파일을 참조하여 규칙에 위배되지 않는 코드를 작성한다.
- `AnimationController`는 반드시 `StatefulWidget`의 `initState`에서 생성하고 `dispose()`에서 해제한다. `SingleTickerProviderStateMixin` (1개) 또는 `TickerProviderStateMixin` (복수) 사용.
- 한글 IME(천지인 등) 입력을 허용하는 `TextInputFormatter`는 `FilteringTextInputFormatter.allow()` 대신 `_AllowedCharsFormatter` 패턴(denied regex + composing 구간 스킵)을 사용한다.
- 비동기 작업 중 화면 이탈을 막을 때는 `PopScope(canPop: !_isLoading)`으로 Scaffold를 감싼다. 화면 터치 차단은 `Stack` + `ColoredBox` 오버레이로 처리한다.
- `Dialog` 위젯은 내부적으로 키보드 높이를 처리하므로, builder에서 `Padding(bottom: viewInsets.bottom)`을 별도로 추가하지 않는다.
